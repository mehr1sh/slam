# Synthetic Stanford Bunny RGB-D sequence

The controlled evaluation sequence of the SLAM pipeline: a rendered test object
with exact ground-truth camera poses, used for development and debugging.

This dataset is generated by `tests/synthetic/render_bunny_test.cpp` from
`data/meshes/bunny/bun_zipper.ply`. It is reproduced byte-for-byte by
(run from `build/`):

```bash
./render_bunny_test ../data/meshes/bunny/bun_zipper.ply ../data/synthetic_bunny \
    --num-frames 36 --radius-scale 4 --height-scale 1
```

| File | Content |
|---|---|
| `000000.png` … `000035.png` | 640×480 RGB renders (8-bit, BGR as written by OpenCV) |
| `000000_depth.png` … `000035_depth.png` | 16-bit depth, value = depth in metres × 5000, 0 = no surface |
| `intrinsics.txt` | `width height fx fy cx cy` = `640 480 520.9 521 325.1 249.7` |
| `groundtruth.txt` | 36 poses, `timestamp tx ty tz qx qy qz qw`, T_wc (camera → world) |
| `pnp_trajectory.txt` | PnP (RANSAC) trajectory, same format; written by `slam_trajectory_test` |
| `icp_trajectory.txt` | ICP trajectory, same format; written by `slam_trajectory_test` |
| `slam_trajectory.csv` | per frame: GT/PnP/ICP positions and quaternions, plus PnP/ICP absolute translation (m) and rotation (deg) errors; written by `slam_trajectory_test` |

The last three files are small reference outputs. They are committed so that
the Blender visualization works without first running the C++ pipeline, and
`slam_trajectory_test ../data/synthetic_bunny` regenerates them identically.
The `slam_` prefix refers to the experiment; the files hold no fused SLAM
estimate.

The images are renderings of the Stanford Bunny and carry its
non-commercial terms (see `THIRD_PARTY_NOTICES.md`).
