# Vision-library removal: dependency audit

This audit was taken at the `baseline-pre-migration` tag. Its goal is a
repository with **zero** dependency on the computer-vision library currently
in use:
- no includes
- no API calls
- no types
- no CMake or package dependency
- no runtime dependency
- no documentation presenting it as a requirement

The per-file tables below are generated by
`python3 scripts/migration/audit_library_refs.py --markdown`. The same scanner,
with `--check`, is the final zero-reference test.

**Scope.** Every file git tracks or would track (tracked + untracked, not ignored).
Generated directories (`build/`, `.pixi/`, `results/data/`, …) are out of scope.
Git history is not rewritten.

## Stage order (as instructed)

1. Baseline freeze (this commit, tag `baseline-pre-migration`).
2. **Features:**
   - new `features/{fast,orientation,brief,matcher}`
   - the body of `find_feature_matches()` replaced
   - **same distance-filter rule** max(2·d_min, 30), so feature extraction is the main variable that changes
   - Bunny compared with the baseline
3. Project-owned RANSAC.
4. Scratch PnP integration (pipeline PnP = scratch DLT in RANSAC).
5. Remaining two-view geometry (J) and matrix types (K, I).
6. Image I/O (A, B).
7. Image processing and drawing (C, L).
8. Removal of the package/build dependency (M), clean build, `ldd` check.
9. Documentation cleanup (N).
10. Final zero-reference audit (`audit_library_refs.py --check`).

Each stage is a separate commit. After each one:
- the full test suite runs (`scripts/migration/run_test_suite.sh`)
- the Bunny metrics are recorded and compared with the previous checkpoint
  (`scripts/migration/bunny_metrics.py OUT --compare PREV`), under `docs/migration/<checkpoint>/`

## Notes and risks found during the audit

- **Feature types cross every module boundary.** `KeyPoint`/`DMatch` appear in
  27 files. The feature checkpoint therefore keeps `find_feature_matches()`'s
  signature and converts project `Keypoint`/`Match` at that one boundary. The type
  migration of the 11 callers happens in the types stage. This is the only
  transitional adapter, and it is removed in stage 5.
- **Images are still read with the library** until the image-I/O stage. In the
  feature checkpoint, `find_feature_matches()` converts the decoded BGR buffer
  with the project's own greyscale function before any project feature code runs.
- **`scripts/generate_results.py` parses the PnP call** in
  `tests/synthetic/slam_trajectory_test.cpp` with a regex (line 163) to label
  figures. It must be updated in the PnP stage.
- **Learned descriptor pattern.** `tests/unit/orb_from_scratch_test.cpp` (book code)
  contains the learned ORB sampling table, which originates in the library.
  It is **not** reused: the new BRIEF uses its own seeded Gaussian pattern.
- **Random numbers.** The two curve-fitting demos draw noise from the library's
  RNG. Replacing it changes the noise samples, and therefore their printed
  numbers. That is expected and will be documented.
- **Dataset PNG bytes.** `render_bunny_test` writes the dataset with the
  library's PNG writer. After the image-I/O stage, regenerated files must match
  **pixel for pixel**. Byte identity of the compressed files is not expected.
- **Committed trajectories.** `data/synthetic_bunny/{pnp,icp}_trajectory.txt` and
  `slam_trajectory.csv` are the baseline pipeline's output. Checkpoints record
  new outputs under `docs/migration/`. Replacing the committed files is a
  separate, explicit decision.
- **zlib.** PNG compression is DEFLATE. The project will use zlib, a
  general-purpose compression library and not a vision library, for it. Its
  headers are not in the pixi environment, so `zlib` is added in the image-I/O stage.
- **Pre-existing defect.** `orb_from_scratch_test` (book code) has an
  intermittent out-of-bounds read. It passed in the baseline run; see
  `baseline/tests/`.
